## 3. Token Persistence

### Current State
`TokenStorageImpl` already uses `com.russhwolf:multiplatform-settings-no-arg` v1.3.0, which persists to `SharedPreferences` (Android) and `NSUserDefaults` (iOS). The CLAUDE.md "in-memory only" note is incorrect and will be removed.

### Optimization for Option B Migration
Currently `TokenStorageImpl` constructs `Settings()` inline. Change to constructor injection:

```kotlin
class TokenStorageImpl(private val settings: Settings) : TokenStorage
```

Koin binding: `single<TokenStorage> { TokenStorageImpl(Settings()) }`

**Option B migration (future):** Replace `Settings()` with an encrypted settings instance in AppModule — no other code changes required. The `TokenStorage` interface, `TokenStorageImpl`, and all callers remain unchanged.

## 4. Infrastructure — `.env` Secrets + Coil 3

Three secrets are read from a `.env` file at project root (gitignored) at Gradle sync via `buildkonfig`:

```
GOOGLE_CALENDAR_ID=church@gmail.com
GOOGLE_CALENDAR_API_KEY=AIzaSy...
PCLOUD_PUBLIC_CODE=XXXXXXXXXX
```

Empty-string fallbacks mean a missing `.env` won't break the build; features simply won't load data at runtime until secrets are provided.

**Coil 3** (`io.coil-kt.coil3:coil-compose` + `coil-network-ktor3`, v3.1.0) is added for image loading in the Album screen.

## 6. 앨범 — pCloud Photo Album

### Data Flow
1. `GET https://api.pcloud.com/getpublinkcontents?code={PCLOUD_PUBLIC_CODE}` → list of image file entries
2. For each file, `GET https://api.pcloud.com/getpublinkdownload?code={code}&fileid={fileId}` → CDN URL (valid ~1h)
3. CDN URLs resolved concurrently in ViewModel; grid shows placeholder cells until each URL resolves

### MVP Constraints
- Flat folder only (no subfolders)
- Image formats: `.jpg`, `.jpeg`, `.png`, `.webp`
- URLs cached in ViewModel for session lifetime (no disk cache needed for MVP)

### Screen Design
- **AlbumScreen:** 3-column tight grid (Google Photos pattern). Unresolved cells show `surfaceContainerLow` placeholder. Tap → PhotoViewerScreen.
- **PhotoViewerScreen:** Full-screen `AsyncImage` (ContentScale.Fit) with back arrow top bar.

**Screen reference:** Run `lazyweb:lazyweb-quick-references` before implementing — search for photo grid / album patterns.

### Architecture
```

  domain/repository/AlbumRepository.kt
  data/model/PCloudFolderResponse.kt
  data/model/PCloudDownloadResponse.kt
  data/repository/AlbumRepositoryImpl.kt
  presentation/AlbumUiState.kt
  presentation/AlbumViewModel.kt
  presentation/AlbumScreen.kt
  presentation/PhotoViewerScreen.kt
```

## 7. 캘린더 — Google Calendar (Read-Only)

### Data Source
Google Calendar API v3, API-key auth (no OAuth). Church admins share their calendar with the church Google account; events appear in the church account's calendar and are fetched read-only.

```
GET https://www.googleapis.com/calendar/v3/calendars/{calendarId}/events
    ?key={apiKey}
    &timeMin={firstDayOfMonthISO}
    &timeMax={firstDayOfNextMonthISO}
    &orderBy=startTime&singleEvents=true&maxResults=100
```

Absolute URL → Ktor `NetworkClient` base-URL injection is bypassed automatically.

### Screen Design
Single screen with two zones:

```
┌─────────────────────────────┐
│  캘린더                       │
│  < 2026년 6월 >              │  ← month navigation
│  [7-col month grid]          │  ← dots on event days, tap to select
│                              │
│  6월 18일 일정               │  ← filtered to selected day (or all-month)
│  ┌───────────────────────┐   │
│  │ 주일 예배 · 오전 11:00 │   │  ← tap → ModalBottomSheet detail
│  └───────────────────────┘   │
└─────────────────────────────┘
```

- Month grid: Zeller's congruence for day-of-week calculation (no external date library needed)
- Selected day highlighted with `primary` circle; event-day dot below day number
- Tapping a day again deselects it (shows all-month events)
- Event detail: `ModalBottomSheet` with title, date/time, location, description — no separate route

**Screen reference:** Run `lazyweb:lazyweb-quick-references` before implementing — search for calendar / agenda patterns.

### Architecture
```

  domain/repository/CalendarRepository.kt
  data/model/GoogleCalendarEventsResponse.kt
  data/repository/CalendarRepositoryImpl.kt
  presentation/CalendarUiState.kt

  presentation/CalendarScreen.kt
```

## 8. Design System Compliance

All new screens must conform to `designs/dn_app/DESIGN.md`:
- No 1px borders — use background shifts for separation
- No pure black — warm charcoal (`onSurfaceVariant`) for body text
- Rounded corners everywhere — `shapes.large` / `shapes.extraLarge`
- Surface hierarchy: `surface` → `surfaceContainerLow` → `surfaceContainerLowest`
- Lazy web references **required** before building any new screen from scratch
